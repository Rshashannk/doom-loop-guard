# PRD: doom-loop-guard v0.3, works with every toolchain (Unreal included)

**Date:** 2026-11-26 · **Status:** reviewed (built; awaiting Shashannk's review before merge) · **Owner:** Shashannk

## Problem
Someone on X said they would try the plugin on an Unreal Engine project. Shashannk asked for Unreal support, and then for the plugin to suit every environment and domain, big or small, with no loose ends.

Up to v0.2, the plugin decided "is this the same error?" by cleaning the error text and hashing the whole of it. That works for test runners with short output. It breaks on real build output. We captured real failures from gcc, clang, make -j, ninja, Go, Rust (cargo build and cargo test), javac, tsc, jest and pytest in a Linux container. Then we ran each one again with nothing changed except what really changes between runs: lines moved because the agent edited the file, parallel output order, and temp file names. Eight of the eleven got a different fingerprint for the same error:

| Toolchain | Why v0.2 saw a "new" error |
| --- | --- |
| gcc, clang (make -j4) | Code-frame gutters (`  12 \| code`) carry line numbers. Parallel jobs print in a different order each run |
| ninja | Same as gcc, plus `[1/2]` progress counters |
| GNU ld | The temp object name is random (`/tmp/ccyqhxXF.o`) |
| cargo build | Code-frame gutters |
| cargo test | The panic line prints the thread id, which changes every run |
| tsc (and MSVC, dotnet, UnrealHeaderTool) | Locations are written `file(12,5)`, which v0.2 did not strip |
| jest | Code-frame gutters. From the second run on, jest also adds "estimated" to its time summary |
| go build, javac, pytest | Fine already |

**Live proof** (Claude Code 2.1.332, the same prompt run twice, `make -j4` with two C++ errors, a blank line added before each rerun): with v0.2 the agent ran the failing build 6 times and was never stopped. With this branch it was warned on the 2nd run and stopped on the 3rd.

Unreal Engine adds its own noise on top of MSVC and clang: UnrealBuildTool action counts, timings, unity files that get renumbered (`Module.Game.2.cpp`), and log timestamps (`[2026.11.26-21.45.13:123][  0]`). Logs run to megabytes, with the error at the end, but v0.2 kept only the first 50 KB. Unreal also has failures that no code change can fix, such as "Unable to build while Live Coding is active", and the editor can exit 0 while automation tests fail.

## Target user
Anyone running Claude Code on a codebase that compiles, links, type-checks or lints. That covers game engines (Unreal, Unity, Godot), native C/C++ (MSVC, gcc, clang, CMake, Ninja, Make, Bazel), .NET, JVM (Gradle, Maven, Kotlin), Rust, Go, Swift and Xcode, and TypeScript and Python type checkers. It works on Windows, macOS and Linux, in small repos and in large monorepos (turbo, nx, pnpm workspaces).

## MVP stories (P0)
1. **Build failures fingerprinted by their diagnostics.** As a developer whose agent is stuck on a compile error, I want the same error to count as the same error, even when lines move or parallel jobs print in a different order.
   - If the command is a build, compile, type-check or lint command, or the output is clearly a build log, the fingerprint uses only the error diagnostics. Each one is reduced to file name, severity, error code and message, then de-duplicated and sorted. Warnings, notes, progress lines and summaries ("2 errors generated") are ignored.
   - Fixing one of several errors gives a new fingerprint, because that is progress.
   - Formats covered: MSVC, MSBuild, dotnet, tsc, UnrealHeaderTool and fxc (`file(12,5): error C2065:`), gcc, clang, swiftc, javac and mypy (`file:12:5: error:`), MSVC and GNU/LLVM/Apple linkers, rustc (`error[E0425]` with its `-->` line), Go, Kotlin, Maven, Bazel, pyright and tsc `--pretty`. Localised compilers (German, French, Spanish, Italian, Polish, Russian, Japanese, Korean and Chinese words for "error") are covered too.
   - Lines prefixed by monorepo task runners or docker compose (`web:build: `, `api-1  | `) are matched after the prefix is removed.
   - Guard against false loops: a stray `file:12: error:` line in a test log never switches the mode on unless the command is a build or the line has an error code. `cargo test` output never collapses to "error: test failed".
2. **Unreal Engine.** As an Unreal developer, I want UBT, UHT, linker, AutomationTool and editor automation failures handled correctly.
   - Unreal is recognised from the command (Build.bat/.sh, RunUAT, UnrealEditor-Cmd, .uproject) or from the log alone, so wrapper scripts work. A project's own `build.sh` is not taken for Unreal.
   - Log prefixes, `[File:…] [Line: N]`, renumbered unity files and action counts are noise. Values in test assertions are not.
   - `UnrealEditor-Cmd … Automation RunTests` that exits 0 with `Result={Fail}` or `TEST COMPLETE. EXIT CODE: 1` counts as a failure.
3. **Environment hints.** As a developer, I want to be told on the first failure when retrying cannot help.
   - One hint per kind per session for: Live Coding active, a conflicting UnrealBuildTool, a locked output file (LNK1104 on a dll, EBUSY, "being used by another process"), out of memory (C1060, exit 137, JavaScript heap, OutOfMemoryError) and a full disk (ENOSPC, "not enough space on the disk").
   - `hints: false` turns them off.
4. **Long builds that hit the shell timeout.** As a developer with a 40-minute build, I don't want "timed out" counted as a repeated error, because each rerun continues the build.
   - A timeout of a build command adds a hint and does not count toward the same-error rule. It still counts toward the same-command rule (stop at 6). Timeouts of other commands, such as a hanging test, count as before.
5. **Generated files.** As a developer, I want a warning before the agent edits a file that the next build regenerates.
   - `*.generated.h`, `*.gen.cpp` and Unreal `Intermediate/` files, protobuf output, `*.g.cs` and `*.g.dart`, `__generated__/`, `node_modules/`, and build output such as `target/debug`, `obj/Debug` and `.next`. One warning per file per session. `generatedFiles: "off"` turns it off.
6. **Huge logs.** As a developer, I want the error found even at the end of a multi-megabyte log.
   - The diagnostics scan reads the whole input, up to the 20 MB stdin cap. The generic normalizer keeps the first 10 KB and the last 40 KB instead of the first 50 KB.
7. **Windows and PowerShell.** As a Windows developer, I want the same behaviour as on Linux.
   - Paths with spaces and drive letters, CRLF, MSBuild `2>` prefixes and `[project.vcxproj]` suffixes are all handled. The PowerShell tool is treated like Bash. `$LASTEXITCODE`, `%ERRORLEVEL%`, `| Select-Object -Last N` and `| tee` are understood.

## Later
- Captured logs from real Unreal, MSVC, Xcode and Unity projects as extra fixtures. Today those fixtures are built by hand from the documented formats.
- Per-language test-runner signatures (jest and pytest failure blocks sorted), for test suites that run in parallel.
- A `toolchains` section in the config for custom diagnostic patterns.

## Out of scope
- Running or wrapping builds. The plugin still only reads what Claude Code hands its hooks.
- Detecting loops inside the Unreal editor GUI. The plugin sees only what Claude runs.

## Decided
- **Compatibility:** output that has none of the new patterns hashes exactly as in v0.2. This is pinned by `test/fixtures/compat-v0.2.json`. Build failures that v0.2 remembered get a new fingerprint once, so their memory entry is replaced on the next failure, and the old one expires after `memoryDays`. `fingerprint: "legacy"` restores v0.2 hashing.
- No new thresholds. The same-error and same-command limits are unchanged.

## Open questions & assumptions
- Assumed from Unreal's source and user reports, not observed: the editor can exit 0 when automation tests fail. Detection only fires when failure markers are present, so a wrong assumption costs nothing.
- In our live run, Claude Code 2.1.332 moved a timed-out command to the background and sent no failure event. The timeout handling applies when a timeout does arrive as a failure.
